# S7. pyslang для precheck и хэша

- Дата: 2026-10-25
- Вопрос ([spikes-and-risks.md](../../specs/plan/spikes-and-risks.md)): разбор решения отдельно от тестбенча; белый список по `SyntaxKind`; запрет любых директив препроцессора; печать канонического текста без комментариев с сохранением номеров строк; устойчивость AST-хэша; время на 2000 строк.
- Критерий успеха: все случаи `tests/security` уровня precheck ловятся; канонический текст компилируется Verilator и yosys-slang; < 300 мс.
- Итог: **критерий выполнен, кроме проверки yosys-slang** — его ещё нет в образе (появится в T3.1a, проверка переносится туда). pyslang подходит для `precheck` целиком; нужны уточнения specs/07 §2.1 (см. ниже).
- Стенд: ветка `spike/s7-pyslang-precheck`, каталог `spikes/s7-pyslang-precheck/` (в основную ветку не переносится; корпус `cases.py` и `corpus/` пригодится для `tests/security` и тестов T0.7a).

## Условия

Образ тулчейна профиля `2026.10.1`: pyslang 12.0.0, Python 3.13, Verilator 5.052. Контейнер с ограничениями песочницы на `runc`, Docker Desktop (WSL2), 2 CPU. gVisor не проверялся (S2).

Прототип `precheck.py` выполняет шаги specs/07 §2.1 по порядку: лимиты размера → лексер ищет директивы → разбор → канонический текст → белый список и правила → элаборация (лимиты, объём состояния, интерфейс) → `code_hash` и AST-хэш.

## Выводы

1. **Директивы ловить лексером, а не в дереве.** `SyntaxTree.fromText` запускает препроцессор: `` `include "/etc/passwd" `` прочитал бы файл, а `` `define `` раскрылся бы ещё до проверки. `pyslang.parsing.Lexer` отдаёт каждую директиву и макрос отдельным токеном (`Directive`, `MacroPaste` и т. п.) без их выполнения — по ним и отказываем, до разбора.
2. **Канонический текст печатать из токенов**, заменяя каждый символ комментария пробелом и сохраняя переводы строк: совпадают и строки, и колонки, диагностики Verilator указывают точно в код пользователя. Хвостовые переводы строк после последнего токена (у файла с одним модулем токен конца файла не входит в корень дерева) берутся из исходника.
3. **Белый список по видам узлов работает**, но одних видов мало — нужны правила поверх них:
   - ровно один `ModuleDeclaration` с именем `top`, больше ничего на верхнем уровне;
   - `@(...)`/`@*` только как первый оператор `always`/`always_ff`; `always` без события запрещён;
   - функции только `automatic`;
   - системные имена — по своему белому списку (это токены, а не узлы);
   - `::`, `$unit`, `$root` запрещены по токенам (`ScopedName` с точкой нужен для полей структур);
   - ссылки вверх по иерархии (`tb.secret`) ловит элаборация решения отдельно: имя не объявлено.
4. **Имена видов узлов проверять при загрузке.** В прототипе два вписанных по памяти имени (`BreakStatement`, `OpenRangeExpression`) молча не существовали; в slang это `JumpStatement` и `ValueRangeExpression`. Список задаётся через `SyntaxKind[name]`, опечатка — ошибка импорта. Тот же риск при обновлении slang: новый профиль тулчейна прогоняет корпус.
5. **Лимиты элаборации slang недостаточны**: `maxGenerateSteps` и `maxConstexprSteps` ловят генерационные «бомбы», ширина упакованного типа ограничена самим slang (16 Мбит), но распакованный массив `logic [7:0] m [2**24]` slang принимает — Verilator выделил бы под него 128 Мбит. Нужен свой лимит суммарного объёма переменных и цепей (в прототипе 2²⁰ бит, по AST после элаборации).
6. **Время.** В процессе — 150 мс на предельном решении, критерий выполнен с запасом. Отдельный процесс на отправку — около 350 мс; это доли процента от бюджета Run (NFR-PERF-01), но под gVisor будет больше — S2 измерит. Запас для оптимизации: один обход дерева вместо трёх, более дешёвая сериализация хэша.

## Рекомендации для T0.7a / T0.7b

- Перенести порядок шагов прототипа; корпус `cases.py` и `corpus/good/` — основа тестов T0.7a и случаев precheck в `tests/security/` (T1.8).
- Лимиты (`MAX_STATE_BITS`, `maxGenerateSteps = 10 000`, `maxConstexprSteps = 100 000`, размер кода) — в конфигурации, не константами.
- Список видов узлов — вместе с языковым модулем, с проверкой имён при импорте и тестом «новый вид запрещён».
- Вызов `void'(f(...))` попадает в запрет (`VoidCastedCallStatement`) — разрешённым функциям он и не нужен; закрепить тестом.
- Проверку канонического текста yosys-slang добавить в T3.1a.
