# Спайки и риски

## 1. Спайки (прототипы до основной разработки)

Каждый спайк — отдельная ветка `spike/<id>`, ограничение по времени, результат — короткий отчёт в `docs/spikes/<id>.md` с цифрами и рекомендацией, правка соответствующего ADR. Код спайка в основную ветку не переносится, кроме тестовых корпусов.

| ID | Вопрос | Что сделать | Критерий успеха | Блокирует | Бюджет |
|---|---|---|---|---|---|
| **S1** | Какое SVA реально поддерживает связка yosys-slang + SBY? | Корпус из ~20 свойств на FIFO и счётчике: immediate с `$past`/`$rose`/`$stable`, `cover`, `assume`, `bind`, отдельно стоящие конкурентные `assert property` с `\|->`/`\|=>`, `##N`, `disable iff`; объявления `property` (по исходникам yosys-slang дают `SVAUnsupported` — подтвердить); для каждого — ожидаемый и фактический результат; сравнить с `read -formal` | Подмножество, достаточное для свойств демо-задач, работает детерминированно; корпус становится регрессией образа | ADR-0005, T5.1 | 3 дня |
| **S2** | Сколько стоит сборка Verilator в песочнице? | На VPS AEZA (Нидерланды) целевой конфигурации: проверить, что gVisor запускается; замер Run на FIFO: runc vs runsc (`systrap`; `kvm` — если доступна вложенная виртуализация), с предсобранным рантаймом и без, `--trace-fst` и `--x-initial unique` вкл/выкл, `-j`, `-O0/-O1/-O3`, холодный/тёплый кэш пакета; CPU-секунды на проверку | Run p50 < 10 с на 2 vCPU под gVisor; цифры CPU-секунд для бюджета | ADR-0003, T1.2a | 3 дня |
| **S3** | Встраивается ли Surfer? | Web-версия Surfer на отдельном origin в iframe с `sandbox="allow-scripts"` без `allow-same-origin`; загрузка FST из байтов, переданных через `postMessage`; программное добавление сигналов, курсор, зум, тема; размер бандла и время загрузки; открывается ли FST текущей версии Verilator | Все действия FR-WAV-01/03/04 выполняются из родительской страницы через адаптер; загрузка < 2 с | ADR-0004, T1.17 | 2 дня |
| **S4** | Метрики синтеза | yosys-slang с `--no-synthesis-define --no-default-translate-off-format` на 5 демо-задачах; Nangate45; OpenSTA с фиксированными `set_driving_cell`/`set_load` vs `abc -D`/`sta`; подготовка нетлиста (`hilomap`, `splitnets -ports`, `write_verilog -noexpr`); симуляция нетлиста на внутренних вентилях Yosys в Verilator (корректность и стоимость); время синтеза; детерминизм (20 прогонов, 2 машины); способ поставки liberty с `LICENSE` | Метрики совпадают побайтно; синтез типовой задачи < 5 с; симуляция нетлиста проходит для эталонов и ловит подставной расходящийся нетлист; скрипт зафиксирован | ADR-0007, T3.1a | 3 дня |
| S5 | Окно трассы FST | `$dumpvars` на такте начала и `$finish` на такте конца по плюс-аргументам в Verilator с `--timing`; совпадение тактов при повторе с тем же сидом (включая случайную инициализацию); размер FST окна | Окно воспроизводимо, FST окна FIFO < 1 МБ | ADR-0004, T0.5 | 1 день |
| S6 | PTY, отмена и права под gVisor | `exec` с PTY: построчный вывод `$display` и Yosys; лимит вывода; уничтожение процессов между этапами (`kill -KILL -1` от непривилегированного пользователя); `kill` контейнера во время компиляции; время старта контейнера; прототип `apx-sandboxd` и сравнение с rootless Docker + `runsc` | Строки приходят ≤ 200 мс; отмена ≤ 1 с; нет зомби и выживших процессов; выбран способ управления контейнерами | ADR-0003, T1.2a | 2 дня |
| S7 | pyslang для precheck и хэша | Разбор решения отдельно; белый список по `SyntaxKind`; запрет любых директив препроцессора; печать канонического текста без комментариев с сохранением номеров строк; устойчивость AST-хэша; время на 2000 строк | Все случаи `tests/security` уровня precheck ловятся; канонический текст компилируется Verilator и yosys-slang; < 300 мс | T0.7a | 2 дня |
| S8 | VK ID и Яндекс ID через Authlib | Тестовые приложения; VK ID: OAuth 2.1, PKCE, `device_id` при обмене кода; получение профиля и email | Вход работает, ответы записаны для тестов | T4.2 | 1 день |

## 2. Реестр рисков

| ID | Риск | Вероятность / влияние | Меры |
|---|---|---|---|
| R1 | Открытый Yosys + yosys-slang поддерживает SVA слишком узко для интересных свойств | средняя / среднее | S1; стиль «immediate + `$past` + checker-логика»; формал — дополнение к тестам, а не основа вердикта |
| R2 | Сборка Verilator под gVisor не укладывается в 10 с | средняя / высокое | S2; предсобранный рантайм; кэш бинарника; `-O0` для сборки; при необходимости — nsjail на выделенных хостах |
| R3 | gVisor на VPS AEZA не работает или медленный | средняя / высокое | S2 на VPS AEZA до T1.2a; платформа `systrap`; запасные варианты — выделенный сервер с KVM или nsjail + seccomp на выделенных VPS воркеров |
| R4 | Surfer нестабилен как встраиваемый компонент или меняет API (официально «unstable») | средняя / среднее | закреплённая версия в `ToolchainProfile`, тонкий адаптер, изолированный iframe; запасной вариант — свой canvas-рендер для окна ошибки |
| R5 | Метрики синтеза недетерминированы или «игровые» (решения подгоняют под особенности ABC/STA) | низкая / среднее | S4; фиксированный скрипт и ограничения STA из образа; точность округления; модерация аномалий; формула с версией |
| R6 | Обход проверок: код решения влияет на тестбенч, результат или выглядит для синтеза иначе, чем для симуляции | средняя / высокое | запрет препроцессора и белый список синтаксиса; канонический текст для всех инструментов; авторитетный файл результатов и nonce; симуляция нетлиста; уничтожение процессов между этапами; набор `tests/security` |
| R7 | Списывание эталонов из открытого репозитория задач | высокая / низкое | принято (ОВ-7); группировка AST и приоритет раннего автора; эталон открывается после своего Accepted |
| R8 | yosys-slang и Verilator по-разному понимают код | средняя / среднее | канонический текст без директив и комментариев; симуляция нетлиста ловит расхождения поведения; понятное сообщение «не синтезируется» |
| R9 | Нагрузка и стоимость выше ожиданий | низкая / среднее (прогноз ОВ-8: сотни, через год — тысячи проверок в месяц) | квоты из бюджета (S2), отдельная квота на перезапись волн, очередь с позицией, горизонтальное масштабирование воркеров, кэш результатов |
| R10 | Юридические требования к ПДн: GDPR (хостинг в ЕС) и возможная применимость 152-ФЗ к пользователям из РФ | средняя / высокое | минимальный состав ПДн; документы по GDPR до Ф2; консультация юриста по ОВ-18 до запуска входа |
| R11 | Недостаток контента (50+ задач) задерживает запуск | высокая / среднее | `judge new`, руководство автора, ИИ-агенты для черновиков пакетов с обязательным ревью и `judge validate`; привлечение сообщества через PR |
| R12 | Сложность авторизации через российских провайдеров (изменения API VK ID) | средняя / низкое | адаптеры с тестами на записанных ответах; провайдеры отключаемы; в публичной бете только GitHub и email |
| R13 | Bus factor: проект ведёт один мейнтейнер | высокая / среднее | документация для агентов и контрибьюторов, ADR, воспроизводимый стенд одной командой |
| **R14** | Хостинг AEZA под санкциями США (OFAC, 1 июля 2025) и Великобритании: репутация IP-адресов (блок-листы, доставка писем, превью ссылок, корпоративные сети), риск изъятия или отключения, сложности с DPA по GDPR, возможные ограничения сервисов из США в цепочке деплоя | средняя / высокое | принято заказчиком: пока остаёмся на AEZA (ОВ-20); проверить стандартный DPA у AEZA в T2.5; переносимость: инфраструктура описана кодом, хранилище через S3 API, бэкапы у другого провайдера в ЕС; почта — через внешний SMTP-провайдер, а не с IP хостинга; проверка доставки писем и превью ссылок на staging |
| **R15** | Лицензия Nangate45: запрет сравнения с другими библиотеками, «not intended for commercial use», несвободна по критериям Fedora | низкая / среднее | принято заказчиком; явное исключение в проверке лицензий; `LICENSE` в образе; без сравнений между библиотеками в будущем выборе PDK; предупреждение для коммерческих инстансов; запасные варианты — ASAP7, sky130 (ADR-0007) |
| R16 | На лёгких задачах многие решения после синтеза совпадают по метрикам | высокая / низкое | равные метрики делят место (ADR-0006); группировка по AST |
