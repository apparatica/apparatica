# ADR-0014. Наборы параметров: проверка решения при нескольких значениях параметров

- Статус: Принято
- Дата: 2026-11-11
- Связано: ОВ-22, FR-JDG-14, FR-PKG-08, FR-JDG-01, FR-JDG-13, FR-SYN-04, FR-LB-02, NFR-PERF-02, ADR-0006, ADR-0007, ADR-0011

## Контекст
Условия задач описывают параметризованный модуль («`WIDTH` — разрядность, по умолчанию 8»), но решение проверяется при одном наборе значений — значениях по умолчанию из `interface.parameters`. Тестбенч задаёт их константами `localparam`, precheck сверяет интерфейс при них же, синтез получает их через `-G`, обёртка нетлиста в `netlist_sim` требует совпадения с синтезом. Поэтому решение, которое объявляет `parameter WIDTH = 8`, а внутри пишет `logic [7:0]`, проходит все проверки.

Ограничения: ядро не знает SystemVerilog (ADR-0011); новый этап не меняет схему `stage_results` (FR-JDG-01); метрики рейтинга должны оставаться сравнимыми (ADR-0006); Submit укладывается в NFR-PERF-02; пакеты задач открыты (ОВ-7).

## Решение

**Пакет (06 §2).**
- Основной набор — значения по умолчанию из `interface.parameters`. Дополнительные наборы объявляются один раз в `interface.param_sets`: `{id, values}`. `id` — `[a-z][a-z0-9_]*`, уникален, `default` зарезервирован за основным набором; `values` — числовые литералы, не указанный параметр берёт значение по умолчанию; наборы попарно различны и отличаются от основного. Число дополнительных наборов ограничено конфигурацией платформы (по умолчанию 3).
- У этапа — поле `param_sets`: `primary` (по умолчанию), `all` или список `id`. Пакет без `param_sets` проверяется как раньше.
- Поле `stages.synth.params` удаляется: синтез получает значения своего набора. Ни одна задача его не использует.
- Этапы `pipelines.*.run` — только `param_sets: primary`: Run даёт быстрый ответ, остальные наборы проверяет Submit. Это проверяет модель пакета.

**Раскрытие этапов (ядро, 07 §2).**
- Этап с N наборами раскрывается в N экземпляров. Ключ экземпляра основного набора — ключ этапа (`synth`), остальных — `<ключ>@<id набора>` (`synth@narrow`).
- Порядок: по этапам, внутри этапа — основной набор, затем дополнительные в порядке объявления. Так дешёвая симуляция всех наборов идёт до дорогого синтеза. Ранняя остановка (FR-JDG-06) и агрегация вердикта (04 §3.3) работают по экземплярам без изменений.
- Ссылка `design: synth.netlist_generic` разрешается в экземпляр того же набора: `netlist_sim@narrow` берёт нетлист `synth@narrow`. Наборы ссылающегося этапа — подмножество наборов этапа-источника (проверяет модель пакета).
- `leaderboard.order` (`synth.critical_path_ns`) ссылается на ключ этапа, то есть на экземпляр основного набора: метрики рейтинга и метрики эталонов (FR-SYN-04) — только с основного набора. Дополнительные наборы проверяют корректность: синтез проходит, защёлок нет, симуляция нетлиста совпадает. Условие рейтинга FR-JDG-13 — пройдены все экземпляры `netlist_sim`.
- `limits.stage_timeout_s` по ключу этапа действует на каждый экземпляр. Сид отправки — один для всех экземпляров.
- `precheck` не раскрывается: он один раз разбирает решение и сверяет интерфейс при каждом наборе пакета (ширины портов задачи вычисляет slang для каждого набора). Ошибка называет набор. Это дёшево и ловит несовпадение ширин до симуляции и синтеза.

**Языковой модуль SystemVerilog.**
- Ядро передаёт этапу в `StageContext` набор (`id` и значения); как подставить значения в инструменты, решает языковой модуль.
- `tb_top` объявляет `parameter` для каждого параметра интерфейса с тем же именем (вместо `localparam`); `sim` передаёт Verilator `-G<имя>=<значение>`. `synth` передаёт `-G` Yosys, обёртка нетлиста в `netlist_sim` сверяет значения своего набора. `judge validate` проверяет параметры `tb_top` и прогоняет эталоны и мутантов на всех наборах.

**Результаты, API, экраны (04, 05, 08).**
- Экземпляр — отдельная строка `stage_results` с ключом экземпляра; новая колонка `param_set text null` (`id` набора, `default` — основной; `null` — этап только с основным набором). Записи `artifacts` и `waveforms` ссылаются на ключ экземпляра, поэтому трасса упавшего открытого теста на любом наборе записывается как сейчас.
- В API у результата этапа — `param_set` (`id`) и значения набора. Панель результатов группирует экземпляры этапа по наборам и показывает значения набора, в том числе для скрытых тестов: пакет открыт, значения не секрет. Подробности скрытых тестов по-прежнему не показываются (06 §3.4).

**Версии задач.** Добавление или изменение наборов — новая версия задачи по обычным правилам (`version`, `changelog`, при необходимости `leaderboard_epoch`). На момент решения принятых решений в production нет.

## Последствия
- Решение, которое не использует параметры, падает на дополнительном наборе. Автор задачи формулирует требования к параметрам в условии и подбирает наборы, которые их проверяют; руководство автора советует мутанта с жёстко заданной разрядностью.
- Пакеты без `param_sets` работают как раньше; метрики и рейтинги существующих задач не меняются.
- Время Submit растёт примерно пропорционально числу наборов у раскрытых этапов, дороже всего — синтез. NFR-PERF-02 измеряется на типовой задаче с наборами; число наборов ограничено конфигурацией.
- Ключ кэша синтеза и сборки уже включает команды, а значит и значения `-G`: отдельной правки кэша не нужно. Значения — только числовые литералы, поэтому подстановка в скрипты Yosys безопасна.
- Меняется контракт API (поля набора в результате этапа) и схема БД (колонка `param_set`) — работа начинается с PR контракта своей фазы.
- Ядро получает понятие набора параметров (имена и целые значения) — это не SV-специфично: в VHDL то же самое называется generic.

## Альтернативы
- **Копии этапов в пакете** (`sim_full_narrow`, `synth_narrow`, `netlist_sim_narrow` со своими `params`). Модель ядра не меняется, но значения повторяются в нескольких местах, связь синтеза и симуляции нетлиста автор поддерживает вручную, а результаты нельзя сгруппировать по набору. Отклонено.
- **Агрегированные метрики по всем наборам** (сумма или среднее площади и задержки). Сложнее объяснить пользователю, а размер наборов перекашивает вес. Отклонено: рейтинг — по основному набору.
- **Случайные значения параметров на каждую отправку.** Недетерминированно: результаты отправок несравнимы, эталонная модель и условие должны допускать любые значения. Отклонено.
- **Порядок «по наборам»** (все этапы основного набора, затем все этапы следующего). Ошибка на дополнительном наборе находится только после дорогого синтеза основного. Отклонено.
