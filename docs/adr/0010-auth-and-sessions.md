# ADR-0010. Аутентификация, сессии, капча

- Статус: Принято
- Дата: 2026-10-24
- Связано: бриф §2.3, §7; FR-AUTH-*, FR-GST-05; NFR-SEC-05

## Контекст
Провайдеры: VK ID, Яндекс ID, GitHub, Google, Telegram Login, email. Всё опционально и отключаемо; самохостинг без SaaS. Нет готового «всё-в-одном» — это основная доля самописного кода.

## Решение
- **OAuth2/OIDC** — Authlib (Starlette-клиент): Google (OIDC), GitHub (OAuth2), Яндекс ID (OAuth2), VK ID (OAuth 2.1 + PKCE, `id.vk.com`). Каждый провайдер — класс-адаптер с одинаковым интерфейсом «код → `{subject, email, nick, avatar}`» и тестами на записанных ответах.
- **Telegram Login** — проверка HMAC-SHA256 данных виджета с ключом `sha256(bot_token)` и свежести `auth_date` (≤ 1 сутки).
- **Email** — только magic link, **без паролей** (меньше поверхность атаки: нет хранения хэшей, сброса, перебора). Токен 32 байта, в БД — хэш, 15 минут, одноразовый.
- **Сессии** — серверные: случайный токен в cookie `ap_session` (httpOnly, Secure, SameSite=Lax), в БД — хэш; кэш в valkey-cache на 60 с. Скользящее продление, 30 дней.
- **CSRF** — проверка `Origin`/`Referer` + double-submit `ap_csrf` / `X-CSRF-Token` на изменяющих запросах.
- **Гость** — cookie `ap_guest` (подписанный UUID, 1 год).
- **Капча** — ALTCHA (proof-of-work, MIT, самохостинг, без сторонних запросов и cookie; решение ОВ-16) по умолчанию; провайдер — конфиг (возможна Yandex SmartCaptcha). Включается правилами rate limit (FR-GST-05).
- Модуль `auth` изолирован, покрыт тестами; набор провайдеров — `config/providers.yaml` + секреты в env.

## Последствия
- Вход без провайдеров и без SMTP невозможен — такой инстанс работает только в гостевом режиме (допустимо для локальной разработки; в dev — Mailpit).
- Связывание аккаунтов по email автоматически не делается (риск захвата через провайдера без проверки email); привязка — только из настроек вошедшего пользователя.

## Альтернативы
- Готовые решения (Keycloak, Ory Kratos, Authentik) — сильные, но отдельный сервис для самохостинга и нет VK ID/Telegram «из коробки».
- JWT в localStorage — уязвимо к XSS и сложнее отзыв.
- Пароль + email — исключён ради простоты и безопасности.
- reCAPTCHA / hCaptcha — сторонний SaaS и трекинг, противоречит принципам проекта.
