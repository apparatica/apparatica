# ADR-0007. Синтез и метрики: yosys-slang, Nangate45, OpenSTA

- Статус: Принято (PDK — Nangate45, решение ОВ-3); скрипт подтверждён спайком S4 ([docs/spikes/s4.md](../spikes/s4.md))
- Дата: 2026-10-24
- Связано: бриф §5; FR-SYN-*; 07 §2.4

## Контекст
Нужны сравнимые ASIC-метрики: площадь, число ячеек и триггеров, задержка критического пути, логическая глубина; признаки латчей и несинтезируемого кода. Родной SV-фронтенд Yosys слаб — бриф предписывает yosys-slang. Метрики должны быть детерминированными (рейтинг, кэш).

## Решение
- **Фронтенд:** `read_slang` (yosys-slang; проект переименован в sv-elab и с Yosys 0.67 встроен в Yosys — плагин не нужен) с флагами `--no-synthesis-define --no-default-translate-off-format`: по умолчанию yosys-slang неявно определяет `SYNTHESIS` и понимает комментарии `translate_off`, а это позволило бы решению выглядеть для синтеза иначе, чем для симуляции. На вход подаётся только канонический текст без комментариев и директив (specs/07 §2.1). Параметры — из `stages.synth.params` (с ADR-0014 — значения набора параметров экземпляра этапа). slang в Yosys и pyslang этапа `precheck` — одна версия (S4: оба на коммите slang `545f88b2`); обновляются вместе.
- **Библиотека:** Nangate45 / FreePDK45 Open Cell Library. Причины: простая однокорнерная liberty, площади и задержки «учебного» масштаба (FIFO из брифа ≈ 836 µm², 0,84 нс — порядок совпадает именно с 45 нм), широко используется в OpenROAD-flow-scripts. Выбор PDK пользователем — задел на будущее; метрики сравнимы только в пределах одной библиотеки.
- **Маппинг:** `read_liberty -lib` → проверка конфликта драйверов (`check` до `synth`, который заменяет их константой) → `synth -flatten` → проверка латчей и петель → (нетлист на внутренних вентилях Yosys для этапа `netlist_sim`, модуль переименован в `<top>__netlist`) → `dfflibmap -liberty` → `abc -liberty` → `hilomap` (`LOGIC1_X1`/`LOGIC0_X1`), `splitnets -ports`, `opt_clean -purge`; `stat -liberty -json` → площадь и ячейки (пустой дизайн — площадь 0); триггеры — ячейки liberty с группой `ff`; `ltp -noff` с исключёнными триггерами liberty → логическая глубина (иначе `ltp` проходит сквозь них); нетлист для STA — `write_verilog -noexpr -noattr`. Скрипт целиком — specs/07 §2.4.
- **Симуляция нетлиста** (specs/07 §2.5) — обязательное условие попадания в рейтинг: синтезированная схема проходит тот же тестбенч с тем же сидом. Нетлист берётся до привязки к Nangate45, поэтому модели ячеек не нужны; этап оборачивает его в `top` с параметрами задачи (07 §2.5).
- **Задержка:** OpenSTA по смапленному нетлисту с фиксированными ограничениями из образа (не из решения): клок на порт с ролью `clock` (без него — виртуальный клок), период из конфига, `set_driving_cell BUF_X1` на входы, `set_load` ёмкостью входа `DFF_X1/D` на выходы, задержки входов и выходов 0. `critical_path_ns = период − WNS` — одна формула для reg→reg, in→reg, reg→out и in→out. `fmax_mhz` — только для задач с клоком. `ltp` — дешёвая логическая глубина как дополнительная метрика.
- **Латчи:** при `forbid_latches` (по умолчанию да) — этап `failed`. Латчем считается и комбинационная петля: неполное присваивание в `always @*` sv-elab превращает в латчи, а в `always_comb` — в петлю `y = … ? y : …` (S4); петли находит `check`, со строкой решения.
- **Детерминизм:** фиксированный скрипт и закреплённые версии. S4: метрики, `stat.json` и оба нетлиста совпадают побайтно в 300 запусках на двух машинах под `runc` и `runsc`; настройка потоков ABC не потребовалась.

## Лицензия Nangate45 — помнить
Лицензия Nangate Open Cell Library 1.0 разрешает распространение с сохранением уведомления, но:
- запрещает измерять библиотеку и сравнивать её с другими библиотеками (benchmarking);
- помечена «not intended for commercial use»; Fedora признала её несвободной.

Для бесплатного некоммерческого проекта это приемлемо (решение заказчика, 2026-10-24).

S4 нашёл, что OpenROAD-flow-scripts распространяет версию `PDKv1.3_v2010_12.Apache.CCL` из Si2 с `LICENSE` Apache-2.0, а заголовок liberty сохранил старое уведомление Nangate. Применима ли Apache-2.0 и снимаются ли ограничения ниже — открытый вопрос ОВ-21; до ответа обязательства действуют.

Обязательства:
1. В образе тулчейна рядом с liberty лежат `LICENSE` и `README.md` из OpenROAD-flow-scripts (версия и источник), уведомление в заголовке liberty сохраняется; T3.1a (образ с синтезом) проверяет это в критериях готовности.
2. Проверка лицензий в CI содержит явное исключение для Nangate45 со ссылкой на этот ADR (NFR-MAINT-07).
3. При будущем выборе PDK пользователем интерфейс **не показывает сравнения метрик между библиотеками**.
4. Коммерческие форки и инстансы должны сами оценить лицензию; это сказано в `docs/deployment.md` и README образа.
5. Риск R15 в реестре рисков; запасные варианты — ASAP7 или sky130.

## Последствия
- В образе тулчейна (профиль 2, T3.1a): Yosys (со встроенным sv-elab и ABC), OpenSTA с CUDD, liberty — образ вырос с 756 до 896 МБ (Yosys 80 МБ, `sta` 7 МБ, liberty 6,5 МБ; на стенде S4 без урезания — 1,09 ГБ). Синтез с STA занимает 1–3,5 с на демо-задачу (S4, цель < 5 с).
- Метрики пригодны для сравнения решений, но не являются sign-off; в UI — пояснение «оценка после синтеза на открытой библиотеке 45 нм».

## Альтернативы
- sky130 — реальный техпроцесс, но тяжёлая liberty и много корнеров; ASAP7 — предиктивный 7 нм, единицы в пс.
- Задержка только по ABC (`abc -D`, `sta` Yosys) — отклонено по итогам S4: в Yosys 0.70 `abc -D` не меняет картирование на демо-задачах и не печатает оценку задержки, `sta` Yosys не читает liberty. OpenSTA стоит 0,2–0,4 с.
- Только `ltp` (глубина в ячейках) — без PDK, но не отражает реальную задержку и площадь.
