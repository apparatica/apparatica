# S5. Окно трассы FST

- Дата: 2026-10-25
- Вопрос ([spikes-and-risks.md](../../specs/plan/spikes-and-risks.md)): `$dumpvars` на такте начала и `$finish` на такте конца по плюс-аргументам в Verilator с `--timing`; совпадают ли такты при повторе с тем же сидом, включая случайную инициализацию; размер FST окна.
- Критерий успеха: окно воспроизводимо, FST окна FIFO < 1 МБ.
- Итог: **критерий выполнен**. Механизм ADR-0004 работает как описан, с двумя уточнениями для `apx_tb_pkg` (см. «Рекомендации»).
- Стенд: ветка `spike/s5-fst-window`, каталог `spikes/s5-fst-window/` (в основную ветку не переносится).

## Условия

Образ тулчейна профиля `2026.10.1` (Verilator 5.052), сборка `apx-verilate --x-assign unique --x-initial unique -Wno-fatal -Wno-lint -j 2`, запуск с `+verilator+rand+reset+2`. Контейнер с ограничениями песочницы (specs/07 §5.1) на `runc`, Docker Desktop (WSL2), 2 CPU. gVisor не проверялся — это S2.

Стенд: синхронный FIFO 16×8 с мутантом, ошибка которого проявляется на такте, зависящем от сида; случайные push/pop против модели-очереди; упрощённая часть `apx_tb_pkg`, отвечающая за окно (`+apx_trace_from`, `+apx_trace_to`, `+apx_trace_file`, счётчик тактов `apx_tick()` на каждом фронте).

## Результаты

| Проверка | Результат |
|---|---|
| `$dumpfile` + `$dumpvars` без аргументов из функции пакета | компилируется и работает с `--timing` |
| Начало записи | на шаге вызова `$dumpvars`: первая отметка FST — фронт такта начала окна, с полным дампом значений (`$dumpvars` в VCD) |
| Конец записи | `$finish` на такте конца закрывает FST корректно: файл читается `fst2vcd`, последняя отметка — фронт такта конца |
| Такт расхождения без трассы и с окном `[T-64, T+16]` | совпадает на 20 из 20 сидов (T от 12 до 530) |
| Другой сид случайной инициализации (`+verilator+seed`) | положение расхождения не меняется (у FIFO корректный сброс) |
| Два прогона с одним сидом | содержимое трассы одинаково (VCD без `$date` совпадает); байты FST различаются только датой в заголовке |
| Окно, начинающееся с такта 0 | работает: запись с `#0` |
| Размер FST окна (81 такт, 50 сигналов) | 1,3–2,2 КБ |
| Размер FST всего прогона (3000 тактов) | 37 КБ |
| Размер FST 200 000 тактов | 2,4 МБ |
| Время симуляции 200 000 тактов: сборка без `--trace-fst` / с трассой, но без записи / с записью (3 повтора) | 216–223 мс / 214–270 мс / 487–516 мс |
| Сборка стенда через `apx-verilate` | 3,3 с |

## Выводы

1. Окно по ADR-0004 воспроизводимо: повторный прогон того же бинарника с тем же сидом даёт то же расхождение, а включение записи не меняет поведение модели.
2. Запись начинается **на** шаге вызова `$dumpvars` (не на следующем, как сказано в ADR-0004), со всеми значениями на этот момент — пользователь видит состояние на такте начала окна.
3. FST окна на порядки меньше критерия; даже полная трасса небольших задач укладывается в него. Окно 80 тактов оставляем: оно ограничивает и время повторного прогона, и объём.
4. Вкомпилированная, но выключенная трасса на этом стенде не отличается от сборки без неё в пределах разброса замеров; включённая запись замедляет симуляцию примерно в 2,3 раза — это касается только повторного прогона в окне. Отдельная сборка с трассой не нужна. Стоимость компиляции с `--trace-fst` по-прежнему измеряет S2.
5. FST недетерминирован побайтно из-за даты в заголовке. Регрессия детерминизма (specs/09 §4.1) должна сравнивать `tb_result.jsonl` и метрики, как и написано, а не FST; если понадобится сравнивать трассы — по содержимому без заголовка.

## Рекомендации для T0.5 (`apx_tb_pkg`)

- Окно реализовать как в стенде: счётчик тактов и проверка границ в функции, которую тестбенч вызывает на каждом активном фронте (`always @(posedge clk) apx_tick();` вместо голого `apx_cycle++`); `$dumpvars` без аргументов — пакет не знает имени модуля тестбенча; при `+apx_trace_from=0` запись начинается сразу в `apx_suite_begin()`.
- **В режиме окна расхождение не завершает прогон**: тестбенч продолжает работу до `+apx_trace_to`, иначе окно обрывается на такте расхождения и «после» не видно. Без окна — остановка на первом расхождении, как в specs/06 §3.1.
- Оркестратор при повторном прогоне сверяет такт первого расхождения с первым прогоном; несовпадение — признак недетерминированного тестбенча (ошибка задачи, алерт), окно не показывается.
- Если `T < 64`, окно начинается с такта 0.

## Что меняется в документах

- ADR-0004: S5 подтверждён; уточнены начало записи, поведение тестбенча в режиме окна и сравнение трасс.
- specs/06 §3.2: в режиме окна `apx_tb_pkg` завершает прогон на `+apx_trace_to`, а не на расхождении.
