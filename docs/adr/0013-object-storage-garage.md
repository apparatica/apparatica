# ADR-0013. Объектное хранилище: Garage

- Статус: Принято; возможности проверены в T0.19 (2026-10-26) на Garage v2.1.0
- Дата: 2026-10-24
- Связано: specs/07 §4.4, §5.3; NFR-SEC-03; бриф §7

## Контекст
Нужно S3-совместимое хранилище для пакетов задач, артефактов (логи, FST, нетлисты), кэша сборок и статики просмотрщика волн. Оно должно самохоститься и подниматься в `docker compose`. Бриф предлагал MinIO, но MinIO Community с конца 2025 года больше не развивается: Docker-образы не публикуются, проект в режиме поддержки.

## Решение
- **Garage** (Rust, AGPL-3.0, рассчитан на самохостинг и небольшие кластеры) в dev, staging и production.
- Права в Garage выдаются ключу на бакет, а не на префикс, поэтому данные разнесены по бакетам:

| Бакет | Содержимое | `api` | `worker` | `ingest` |
|---|---|---|---|---|
| `packages` | пакеты задач (`<slug>/<version>-<hash>.tar.zst`) | запись (импорт) | чтение | — |
| `artifacts` | логи, события, FST, нетлисты, отчёты | чтение (presigned URL) | запись | чтение |
| `build-cache` | бинарники симуляции | — | чтение и запись | — |
| `waveview` | статика Surfer, раздаётся как сайт с отдельного поддомена | — | — | — |

- Нужные возможности — presigned URL, CORS для `waveview` и страницы задачи, правила жизненного цикла (срок хранения FST, логов Run, кэша сборок). Их проверяет T0.19. Если какое-то правило жизненного цикла не поддерживается, срок хранения обеспечивает периодическая задача ингестора.
- Код работает с хранилищем только через S3 API (`boto3`/`aiobotocore`), поэтому провайдера можно сменить без изменений кода — например, на объектное хранилище хостинга.

## Проверка в T0.19

Стенд `deploy/compose.yaml`, проверка — `just stand-check` (`deploy/garage/check.py`) через Caddy, как из браузера.

- **Ключи на бакет** работают по таблице выше: `api` пишет `packages` и не пишет `artifacts`, воркер читает `packages` и пишет `artifacts`, `ingest` только читает `artifacts`. Права выдаёт `deploy/garage/setup.py` через admin API v2; ключи импортируются из настроек стенда, поэтому их не нужно переписывать после пересоздания хранилища.
- **Presigned URL** — GET с подменой `Content-Type` и `Content-Disposition: attachment`; изменённая подпись отклоняется. Host запроса входит в подпись: URL подписывается публичным адресом хранилища (на стенде `http://s3.localhost:8080`), а proxy передаёт Host без изменений.
- **CORS** — работает с одной особенностью: если в правиле несколько `AllowedOrigins`, Garage возвращает их все через запятую в `Access-Control-Allow-Origin`, а браузеры такой ответ отвергают. Поэтому одно правило — один origin. Чужой origin получает 403 на preflight и ответ без `Access-Control-Allow-Origin` на простой GET; `*` Garage ставит только на ответы с ошибкой.
- **Жизненный цикл** — правила `Expiration` (дни) и `AbortIncompleteMultipartUpload` принимаются и читаются обратно; фильтр — по префиксу ключа и размеру объекта. Garage применяет правила раз в сутки, удаление в T0.19 не наблюдалось. Кэш сборок (`build-cache`, 1 день) задаётся правилом на весь бакет. Сроки артефактов по виду (FST — 7 дней, логи Run — 30 дней, specs/07 §4.4) префиксами ключей `<yyyy>/<mm>/<submission_id>/…` не выражаются: либо ключи начинаются с вида срока хранения (например, `fst/…`, `run/…`), либо сроки соблюдает периодическая задача ингестора. Выбор — вместе с артефактами (Ф1).
- **Сайт из бакета** — `waveview` отдаётся web-эндпоинтом Garage на своём origin (`http://waveview.web.localhost:8080`); до Surfer (Ф1) там заглушка `index.html`.

## Последствия
- Резервные копии Postgres хранятся не в этом Garage, а у другого провайдера в ЕС (specs/09 §3).
- Garage реализует не весь S3 API; используемое подмножество фиксируется в `docs/deployment.md`.

## Альтернативы
- **SeaweedFS** (Apache-2.0) — больше возможностей, но сложнее в эксплуатации.
- **Ceph RGW** — избыточен для одного сервера.
- **MinIO** — заморожен; образы Chainguard — сторонняя сборка без развития проекта.
