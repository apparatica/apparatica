# Глоссарий

Термины проекта. Используются в коде, документации, спецификации и интерфейсе одинаково.

| Термин | Значение |
|---|---|
| **Задача** (`Problem`) | Единица контента с постоянным `slug`. Имеет последовательность неизменяемых версий. |
| **Версия задачи** (`ProblemVersion`) | Неизменяемый снимок пакета задачи. После публикации не меняется; исправление — новая версия. |
| **Пакет задачи** | Каталог в репозитории задач: `problem.yaml`, условие, шаблон, тестбенчи, формальные свойства, эталоны, мутанты. |
| **Эпоха рейтинга** (`leaderboard_epoch`) | Число в `problem.yaml`. Увеличивается автором, когда изменение версии делает старые результаты несравнимыми (новые тесты, другой интерфейс). Рейтинг ведётся в пределах эпохи. |
| **Отправка** (`Submission`) | Одна проверка кода. Тип: `run` или `submit`. Хранит версию задачи, профиль тулчейна, сид. |
| **Run** | Быстрый прогон на открытых тестах. Не попадает в рейтинг. |
| **Submit** | Полный прогон: открытые и скрытые тесты, синтез, формал. Accepted попадает в рейтинг (для вошедших). |
| **Этап** (`Stage`) | Шаг пайплайна: `precheck`, `lint`, `sim`, `synth`, `formal`. Реализован плагином языкового модуля. |
| **Результат этапа** (`StageResult`) | Статус, длительность, метрики (JSONB со схемой `<stage_type>/v<N>`), сводка, ссылки на артефакты. |
| **Вердикт** | Итог отправки: Принято, Неверный ответ и т. д. (см. `04-domain-model.md`). |
| **Артефакт** | Файл в объектном хранилище: лог, FST, нетлист, отчёт. |
| **Профиль тулчейна** (`ToolchainProfile`) | Docker-образ с закреплёнными версиями инструментов и liberty, плюс версия нормализации AST. Метрики сравнимы только в пределах профиля. |
| **Класс ресурсов** | `light` / `heavy`. Определяет очередь и лимиты по умолчанию. |
| **Сид** | Случайное число на отправку для constrained-random стимулов. Сохраняется, прогон воспроизводим. |
| **Эталонная модель** | Поведенческая модель в пакете задачи, с которой scoreboard тестбенча сравнивает выходы решения. |
| **Эталонное решение** (`ReferenceSolution`) | Синтезируемое решение автора с пояснением; видно пользователю по политике видимости. |
| **Мутант** | Заведомо неверное решение в пакете. `judge validate` требует, чтобы каждый мутант был пойман. |
| **Нормализованный AST-хэш** | Хэш синтаксического дерева без пробелов и комментариев, с каноническими именами локальных идентификаторов. Признак совпадающих решений в рейтинге и подсказка модератору; ключом кэша не служит. |
| **Канонический текст** | Текст решения, заново напечатанный из синтаксического дерева без комментариев (директивы препроцессора запрещены). Только он попадает в инструменты, поэтому все инструменты видят один и тот же код. Его sha256 — `code_hash`, ключ кэшей. |
| **Симуляция нетлиста** (`netlist_sim`) | Этап Submit: синтезированная схема прогоняется тем же тестбенчем с тем же сидом. Без него решение не попадает в рейтинг. |
| **Токен задания** | Подпись API на `{submission_id, attempt_max, exp}`, которую воркер прикладывает к результатам; ингестор принимает результаты только с ним. |
| **`apx-sandboxd`** | Небольшой процесс на хосте воркера — единственный, у кого есть доступ к Docker; создаёт и уничтожает контейнеры песочницы с фиксированными флагами. |
| **Публичная бета** | Открытие сайта для всех после Ф3: вход через GitHub и email, проверка с синтезом и рейтинги. |
| **Группа совпадающих решений** | Записи рейтинга с одинаковым AST-хэшем. Место у самого раннего автора, остальные помечены «совпадает с решением N». |
| **Оркестратор** | Процесс воркера вне песочницы: запускает этапы в контейнере, пишет события в Redis и артефакты в S3. |
| **Песочница** | Одноразовый контейнер под gVisor без сети, с read-only rootfs и лимитами. |
| **Ингестор** (`ingest`) | Фоновый процесс бэкенда (тот же код, что и API, другая команда запуска). Читает результаты проверок, которые воркеры пишут в Redis Stream, и сохраняет их в Postgres: результаты этапов, вердикт, статус «решено», рейтинги. Также следит за зависшими проверками (watchdog) и выполняет периодическую очистку. |
| **SSR** (server-side rendering) | Рендеринг страницы на сервере Next.js: сервер сам запрашивает данные у API по внутренней сети, собирает HTML и отдаёт его браузеру. Нужен для поисковиков, превью ссылок и быстрой первой отрисовки. «SSR-запросы» — эти запросы web → api. |
| **Гость** | Пользователь без входа. Идентифицируется подписанной cookie `guest_id`. |
| **PPA** | Performance, Power, Area. В проекте сейчас: задержка и площадь; мощность — задел. |
| **FST** | Сжатый бинарный формат трасс сигналов (GTKWave/Verilator). VCD не используется. |
| **SVA** | SystemVerilog Assertions. Допустимое подмножество — ADR-0005. |
| **Индустриальный режим** | Пошаговый альтернативный профиль пайплайна задачи (Ф7). Отдельный рейтинг. |
