# ADR-0003. Песочница: одноразовый контейнер под gVisor, все этапы недоверенные

- Статус: Принято (2026-10-25, по итогам спайков [S2](../spikes/s2.md) — Run p50 3,1 с под `runsc`/`systrap` на VPS AEZA — и [S6](../spikes/s6.md) — PTY, отмена, уничтожение процессов, `apx-sandboxd`)
- Дата: 2026-10-24 (редакция по итогам независимого ревью)
- Связано: бриф §6; specs/07 §5; NFR-SEC-01…04, NFR-SEC-10

## Контекст
Verilator компилирует код пользователя в C++ и исполняет его. Yosys, SymbiYosys и slang разбирают код атакующего и тоже могут иметь уязвимости. Нужны изоляция от хоста и сети, лимиты ресурсов и вывода, корректное убийство дерева процессов при отмене, построчный вывод (PTY) и ориентир Run p50 < 10 с. Хостинг — VPS AEZA (Нидерланды) без гарантированной вложенной виртуализации.

## Решение
- **Один контейнер на отправку** из образа тулчейна с рантаймом gVisor (`runsc`, платформа `systrap` — работает без KVM), флаги — specs/07 §5.1. Этапы выполняются через `exec` с TTY. Контейнер уничтожается после проверки или при отмене.
- **Все этапы недоверенные.** Отдельных контейнеров для «доверенных» этапов нет: доверенных этапов не бывает, и это было бы оверинжинирингом. Вместо этого (specs/07 §5.2):
  - каждый этап работает в чистой директории, входные файлы кладёт оркестратор только для чтения;
  - после каждого этапа уничтожаются все процессы непривилегированного пользователя в контейнере; PID 1 контейнера — собственный «жнец» `apx-init` под тем же UID: ядро не доставляет ему `kill -1`, а он забирает осиротевшие процессы (S6: с `sleep infinity` остаются зомби, а `docker run --init` завершается вместе со своим убитым ребёнком);
  - выходные файлы этапов разбираются как недоверенные: сначала размер, затем схема;
  - бинарник симуляции копируется в кэш до первого запуска.
- **Честность вердикта** обеспечивают статическая проверка с белым списком и каноническим текстом, авторитетный файл результатов тестбенча и симуляция нетлиста (specs/07 §2.1, §2.5) — а не изоляция этапов.
- **Docker только у помощника.** Оркестратор не получает docker socket: контейнерами управляет `apx-sandboxd` — небольшой процесс на хосте с фиксированным набором операций и жёстко заданными флагами, доступный через unix-socket. Ошибка разбора недоверенного вывода в оркестраторе не даёт управления Docker. Прототип в S6 добавляет к `exec` около 5 мс. Rootless Docker с `runsc` отклонён по итогам S6: gVisor в этом режиме не создаёт контейнеры, а с `--ignore-cgroups` теряются лимиты памяти и CPU.
- **Нет разделяемого записываемого ccache.** Общий кэш между недоверенными прогонами можно отравить. Объектные файлы рантайма Verilator собираются при сборке образа в статическую библиотеку и лежат в нём read-only; обёртка `apx-verilate` подключает её вместо компиляции рантайма (T0.3: сборка маленького тестбенча с `-j 2` без gVisor — 18 с без библиотеки, 4 с с ней). Предкомпилированные заголовки — кандидат для S2. Кэшируется только конечный бинарник симуляции по ключу `(code_hash, problem_version, toolchain_profile, design)` — его сохраняет оркестратор. *Уточнено в T1.2c:* ключ — sha256 команды сборки и всех её входов (тестбенч, канонический текст решения или нетлист) в области профиля и digest образа тулчейна; бинарник сохраняет этап `sim` через кэш, который даёт ему оркестратор (specs/07 §2.3).
- Пакет задачи монтируется read-only из локального кэша воркера (сверка sha256), рабочая директория — tmpfs.
- Для разработки на Windows/macOS — `SANDBOX_RUNTIME=runc` с теми же флагами; staging и production — только `runsc` (проверка при старте воркера).
- `kvm`-платформа gVisor — только на выделенном сервере или при наличии nested virtualization. S2 проводится на VPS AEZA той же конфигурации, что и production-воркеры.

## Последствия
- Сильная изоляция ценой накладных gVisor на системные вызовы (компиляция C++ интенсивна по файловым операциям; S2 измеряет).
- `apx-sandboxd` — дополнительный небольшой компонент с собственными тестами; его интерфейс не позволяет передать произвольные флаги Docker.
- Повторный Submit после Run без изменений не пересобирает симуляцию.

## Альтернативы
- **Отдельный контейнер для синтеза и формала** — защищает от фоновых процессов симуляции, но не от уязвимостей самих Yosys и SBY; те же гарантии дают уничтожение процессов между этапами и симуляция нетлиста.
- **nsjail** — легче и быстрее, но изоляция уровня namespaces + seccomp при общем ядре с хостом; запасной вариант, если gVisor на VPS AEZA не заработает.
- **Firecracker** — сильнее изоляция, но нужна KVM и своя оркестрация microVM.
- **Judge0, isolate, DMOJ, CMS** — рассчитаны на модель «stdin/stdout и сравнение вывода», без многоэтапного пайплайна, PTY-стриминга и артефактов; свой оркестратор оправдан.
