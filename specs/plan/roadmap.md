# План разработки по фазам

Каждая задача — один PR для ИИ-агента: ограниченная область, тесты в том же PR, ссылка на требования. ID задачи — `T<фаза>.<номер>`; задачи, разделённые на несколько PR, имеют суффиксы `a`, `b`. «Зависит от» — задачи, которые должны быть слиты раньше. Задачи без взаимных зависимостей можно вести параллельно.

Общие правила для каждого PR: CI зелёный (линтеры, типы, тесты); если меняется API — обновлены Pydantic-схемы, `openapi.json` и TS-клиент (источник правды — код, specs/05 §0); если меняется поведение, архитектура, настройка или эксплуатация — обновлена проектная документация в `docs/` (а при изменении требований — спецификация в `specs/`); новые строки UI — в `messages/ru.json`; новые цвета — только токены; изменения судьи, образа или песочницы прогоняют `tests/security/`.

## Обзор фаз

| Фаза | Итог | Выход к пользователям |
|---|---|---|
| Ф0. Фундамент | репозиторий, CI, образ тулчейна, CLI судьи, демо-задачи, ядро API | — |
| Ф1. Ядро решения | гость решает задачу: Run/Submit, консоль, тесты, волны | закрытое тестирование на staging |
| Ф2. Пользователи: минимум | вход через GitHub и email, история, профиль, юридические документы, бэкапы | — |
| Ф3. Качество решений | синтез, симуляция нетлиста, рейтинги, решения, эталоны, шеринг, минимальная модерация | **публичная бета** |
| Ф4. Пользователи: расширение | VK ID, Яндекс ID, Google, Telegram, дашборд и heatmap, импорт гостевых решений | — |
| Ф5. Формал и модерация | формальные проверки, жалобы, полная админка, rejudge | — |
| Ф6. Контент и масштаб | 50+ задач, LSP, схемы нетлиста, нагрузочный тест | **публичный запуск** |
| Ф7. Индустриальный режим | пошаговый режим и отдельный рейтинг | — |

**PR контракта.** Каждая фаза с новыми эндпоинтами начинается с задачи `T<фаза>.0`: Pydantic-схемы, роуты с заглушками (501), сгенерированные `openapi.json` и TS-клиент, MSW-моки. Фронтенд-задачи фазы зависят от PR контракта, а не от реализации бэкенда, и до её готовности работают на моках; интеграция проверяется e2e-тестами фазы. В Ф0 роль PR контракта выполняет T0.18.

Порядок выбран так, чтобы главное отличие продукта — рейтинг решений по метрикам синтеза — появилось сразу после минимальной пользовательской части.
