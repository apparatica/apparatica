# Как внести вклад

> Черновик. Дополняется по мере появления CI, шаблонов PR и руководства автора задач.

Спасибо, что помогаете apparatica. Окружение и команды — в [docs/development.md](docs/development.md), устройство системы — в [docs/architecture.md](docs/architecture.md), план работ — в [specs/plan/roadmap.md](specs/plan/roadmap.md).

## Ветки

Основная ветка — `master`: от неё создаются рабочие ветки, в неё направляются PR.

Имя ветки — `<тип>/<краткое-описание>`: латиница в нижнем регистре, слова через дефис. Если работа относится к задаче плана или спайку, описание начинается с её ID.

| Тип | Когда |
|---|---|
| `feat/` | новая функциональность |
| `fix/` | исправление ошибки |
| `refactor/` | изменение кода без изменения поведения |
| `perf/` | производительность |
| `test/` | только тесты |
| `docs/` | только документация или спецификация |
| `ci/` | CI и автоматизация репозитория |
| `build/` | образы, зависимости, сборка |
| `chore/` | обслуживание: каркас, конфигурация инструментов |
| `problem/` | новые или исправленные пакеты задач в `problems/` |
| `spike/` | прототип из [spikes-and-risks.md](specs/plan/spikes-and-risks.md); в основную ветку не сливается |

Примеры: `chore/t0.1-monorepo-skeleton`, `feat/t1.14-use-submission`, `fix/sse-reconnect-last-event-id`, `problem/t0.11-mux4-counter`, `spike/s2-gvisor-verilator`.

## Коммиты

Сообщение коммита — по [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/): `<тип>: <описание>`, типы те же, что у веток (кроме `problem` и `spike`: для них — `feat`, `fix` или `chore`). ID задачи плана — в скобках в конце первой строки. Подробности — в теле сообщения.

Пример: `chore: scaffold monorepo (T0.1)`, `feat(judge): add verdict aggregation (T0.6)`.

## Pull request

- Один PR — одна задача плана или одно связанное изменение. В заголовке — ID задачи, если она есть.
- `just check` зелёный локально, CI зелёный.
- Тесты — в том же PR.
- PR, который меняет поведение, архитектуру, настройку или эксплуатацию, обновляет `docs/`. Изменение требований — правка `specs/`, изменение принятого решения — новый или исправленный ADR в `docs/adr/`.
- Изменения API — через код: Pydantic-схемы и роуты, затем `just openapi` и обновлённый клиент (specs/05 §0).
- Строки интерфейса — только в `messages/ru.json`, цвета — только токены.
- Изменения судьи, образа тулчейна или песочницы прогоняют `tests/security/`.

## Задачи

Новая задача или исправление задачи — ветка `problem/<id>` с пакетом в `problems/`. Как устроен пакет, что требуется от тестбенча, эталона и мутантов и что проверить перед PR — [руководство автора](docs/problem-authoring.md). Перед PR пакет должен проходить `judge validate`.

## Язык

Документация, условия задач и интерфейс — на русском. Идентификаторы, коды ошибок, комментарии в коде, сообщения коммитов — на английском.

## Лицензии и DCO

- Код платформы — [AGPL-3.0-or-later](LICENSE).
- Пакеты задач в `problems/` — [CC BY-SA 4.0](problems/LICENSE).

Вклад принимается по [Developer Certificate of Origin](https://developercertificate.org/), без CLA: каждый коммит подписывается строкой `Signed-off-by: Имя <email>` (`git commit -s`). Подписью вы подтверждаете, что имеете право передать изменение под лицензией соответствующей части репозитория.
