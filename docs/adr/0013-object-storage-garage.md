# ADR-0013. Объектное хранилище: Garage

- Статус: Принято (возможности подтверждаются в T0.19)
- Дата: 2026-10-24
- Связано: specs/07 §4.4, §5.3; NFR-SEC-03; бриф §7

## Контекст
Нужно S3-совместимое хранилище для пакетов задач, артефактов (логи, FST, нетлисты), кэша сборок и статики просмотрщика волн. Оно должно самохоститься и подниматься в `docker compose`. Бриф предлагал MinIO, но MinIO Community с конца 2025 года больше не развивается: Docker-образы не публикуются, проект в режиме поддержки.

## Решение
- **Garage** (Rust, AGPL-3.0, рассчитан на самохостинг и небольшие кластеры) в dev, staging и production.
- Права в Garage выдаются ключу на бакет, а не на префикс, поэтому данные разнесены по бакетам:

| Бакет | Содержимое | `api` | `worker` | `ingest` |
|---|---|---|---|---|
| `packages` | пакеты задач (`<slug>/<version>-<hash>.tar.zst`) | запись (импорт) | чтение | — |
| `artifacts` | логи, события, FST, нетлисты, отчёты | чтение (presigned URL) | запись | чтение |
| `build-cache` | бинарники симуляции | — | чтение и запись | — |
| `waveview` | статика Surfer, раздаётся как сайт с отдельного поддомена | — | — | — |

- Нужные возможности — presigned URL, CORS для `waveview` и страницы задачи, правила жизненного цикла (срок хранения FST, логов Run, кэша сборок). Их проверяет T0.19. Если какое-то правило жизненного цикла не поддерживается, срок хранения обеспечивает периодическая задача ингестора.
- Код работает с хранилищем только через S3 API (`boto3`/`aiobotocore`), поэтому провайдера можно сменить без изменений кода — например, на объектное хранилище хостинга.

## Последствия
- Резервные копии Postgres хранятся не в этом Garage, а у другого провайдера в ЕС (specs/09 §3).
- Garage реализует не весь S3 API; используемое подмножество фиксируется в `docs/deployment.md`.

## Альтернативы
- **SeaweedFS** (Apache-2.0) — больше возможностей, но сложнее в эксплуатации.
- **Ceph RGW** — избыточен для одного сервера.
- **MinIO** — заморожен; образы Chainguard — сторонняя сборка без развития проекта.
