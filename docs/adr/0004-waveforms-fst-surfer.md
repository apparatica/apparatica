# ADR-0004. Временные диаграммы: FST, окно ошибки повторным прогоном, Surfer в изолированном iframe

- Статус: Предложено (S5 подтверждён 2026-10-25 — [отчёт](../spikes/s5.md); ожидает S3)
- Дата: 2026-10-24 (редакция по итогам независимого ревью)
- Связано: бриф §2.1, §7, §7.2; FR-WAV-*; specs/07 §2.3; NFR-SEC-07

## Контекст
Пользователю нужна трасса вокруг первого расхождения со «ожидаемое vs фактическое». VCD большой; бриф требует FST. Трассировка всего прогона замедляет симуляцию и раздувает хранилище. Прогоны детерминированы (сид, профиль). FST формирует код пользователя, а Surfer его разбирает — значит, файл недоверенный.

## Решение
- **Формат:** только FST (`verilator --trace-fst`). Трассировка компилируется в бинарник всегда (один бинарник на Run/Submit), а включается во время исполнения плюс-аргументами.
- **Окно ошибки:** первый прогон без трассы; при падении открытого теста — повторный прогон того же бинарника с тем же сидом и окном `[T-64, T+16]` тактов. `apx_tb_pkg` вызывает `$dumpvars` на такте начала окна и `$finish` на такте конца: Verilator игнорирует `$dumpoff`/`$dumpon`, а `$dumpvars` начинает запись на шаге вызова, с полным дампом значений на такте начала окна. В режиме окна расхождение не завершает прогон: тестбенч работает до конца окна, чтобы было видно, что произошло после расхождения. Оркестратор сверяет такт первого расхождения повторного прогона с первым; несовпадение означает недетерминированный тестбенч (ошибка задачи), окно не показывается. Скрытые тесты не трассируются.
- **Ожидаемое vs фактическое:** тестбенч объявляет `exp_<port>`; судья передаёт Surfer список сигналов: такт, входы, затем пары `<port>` / `exp_<port>`.
- **Хранение:** 7 дней, затем пересоздание повторным прогоном по запросу (FR-WAV-05, отдельная квота).
- **Просмотр:** Surfer (WASM), закреплённая версия, статика на **отдельном origin** (бакет `waveview` за отдельным поддоменом). Страница задачи встраивает его в iframe с `sandbox="allow-scripts"` без `allow-same-origin`: ошибка в разборе FST внутри Surfer не даёт доступа к cookie и DOM основного сайта. Страница сама скачивает FST и передаёт байты в iframe через `postMessage`; через тот же канал — добавление сигналов, курсор, зум, тема. API сообщений Surfer официально нестабилен, поэтому между ним и сайтом — тонкий адаптер с собственным протоколом; S3 проверяет загрузку из байтов.
- **Версии:** версия Surfer входит в `ToolchainProfile`: формат FST, который пишет Verilator, и просмотрщик обновляются вместе. Регрессия образа проверяет, что FST эталонной задачи открывается в закреплённой версии Surfer.

## Последствия
- Компиляция с `--trace-fst` дороже (S2 измеряет; если заметно — отдельная сборка с трассой только при падении). Исполнение со вкомпилированной, но выключенной трассой по замеру S5 не медленнее сборки без неё.
- FST окна — единицы килобайт (S5: 1,3–2,2 КБ на FIFO).
- Байты FST различаются между прогонами датой в заголовке: детерминизм проверяется по `tb_result.jsonl` и метрикам, а не по FST.
- Повторный прогон удваивает время симуляции упавших Run; ограничено окном и остановкой на первом расхождении.
- Отдельный origin — ещё одно имя в DNS и сертификат в Caddy.
- Лицензия Surfer EUPL-1.2: используется как отдельное неизменённое приложение; EUPL совместима с AGPL-3.0 (ADR-0012).

## Альтернативы
- **Iframe того же origin** — проще, но XSS в Surfer становится XSS основного сайта.
- **Трассировать всегда** — проще, но медленнее и дороже по хранилищу.
- **VCD** — запрещено брифом.
- **Свой canvas-рендер** — полный контроль, но собственный парсер FST в браузере; запасной вариант, если S3 провалится.
