# Документация Apparatica

Проектная документация: как устроена и работает система. Поддерживается в актуальном состоянии — каждый PR, который меняет поведение, архитектуру, настройку или эксплуатацию, обновляет соответствующий документ здесь. Что и в каком порядке планируется сделать — в [спецификации и плане](../specs/README.md).

| Документ | Содержание | Статус |
|---|---|---|
| [architecture.md](architecture.md) | компоненты, как они общаются, путь проверки | целевая архитектура; уточняется по мере реализации |
| [glossary.md](glossary.md) | термины проекта | актуален |
| [adr/](adr/README.md) | архитектурные решения и их причины | актуален |
| [spikes/](spikes/) | отчёты спайков из [spikes-and-risks.md](../specs/plan/spikes-and-risks.md): цифры и рекомендации | S5, S7 |
| [development.md](development.md) | установка окружения, команды `just`, структура репозитория, git-хуки | актуален; запуск стенда добавится в T0.19, генерация API-клиента — в T0.18 |

## Правила

- Документ описывает то, что есть в коде, а не планы. Планы — в `specs/`.
- Изменение кода и документации — в одном PR. Ревью проверяет и то, и другое.
- Решение, которое меняет архитектуру или выбранный инструмент, оформляется ADR в [adr/](adr/README.md).
- Документы пишутся по-русски; команды, пути и идентификаторы — как в коде.
