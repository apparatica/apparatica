# ADR-0009. Возврат результатов: стрим результатов и ингестор

- Статус: Принято
- Дата: 2026-10-24
- Связано: бриф §7.2; 07 §1; NFR-SEC-03, NFR-REL-02

## Контекст
Воркеры не должны иметь доступа к Postgres и секретам API. Бриф допускает возврат результатов «через очередь или внутренний эндпоинт». Результаты этапов нужно сохранять по мере готовности (частичные результаты).

## Решение
- Оркестратор пишет результаты в общий стрим `judge:results` (события `stage_end`, `done`, `attempt_failed`) с `submission_id`, номером попытки и **токеном задания**: API подписывает `{submission_id, attempt_max, exp}` при постановке в очередь. Ключ подписи есть только у API и ингестора, поэтому скомпрометированный воркер не может записать результат для отправки, которую ему не выдавали.
- Процесс `ingest` (код бэкенда, модуль `judging`) читает стрим через consumer group, проверяет токен, делает upsert `stage_results` по `(submission_id, stage_key)` и обновляет `submissions`, агрегирует вердикт по `done` (функцией из `judge.core`; воркер вердикт не считает), обновляет статусы пользователя и рейтинги, публикует в стрим отправки событие `finalized` с итоговым статусом и местом, подтверждает (`XACK`). Необработанные записи перехватываются (`XAUTOCLAIM`) другим экземпляром.
- В том же процессе — watchdog (только страховка, без перепостановки) и периодические задачи (очистка гостевых отправок, процент принятых, снимки рейтинга). При нескольких экземплярах их выполняет только лидер (`SET leader:ingest NX EX 30`).

## Последствия
- Воркеру нужны только Redis и S3; API и воркеры масштабируются независимо.
- Идемпотентность обязательна: повторная доставка и порядок `stage_end` после `done` должны обрабатываться корректно (тесты).
- Задержка «результат → БД» — десятки миллисекунд; UI во время проверки опирается на SSE, а не на БД.

## Альтернативы
- Внутренний HTTP-эндпоинт API — воркер получает сетевой доступ к API и токен; при недоступности API нужны свои ретраи.
- Отдельная Dramatiq-очередь результатов — возможно, но consumer group по стриму проще дочитывать и мониторить.
