# AGENTS.md

Apparatica — открытый тренажёр по RTL на SystemVerilog («LeetCode для цифровой логики»). Проект на стадии спецификации: кода пока нет.

## С чего начать
- `specs/` — спецификация и план (что строим): `specs/README.md`. Перед задачей из плана прочитайте её строку в `specs/plan/roadmap.md` и требования, на которые она ссылается (`specs/01-…`, `02-…`).
- `docs/` — проектная документация (как устроено то, что уже есть): `docs/README.md`, архитектура — `docs/architecture.md`, термины — `docs/glossary.md`.
- Архитектурные решения — `docs/adr/`. Не меняйте принятое решение молча: новый ADR или правка существующего в том же PR.
- Открытые вопросы — `specs/plan/open-questions.md`. Допущения живут в конфигурации, не в константах.

## Правила
- Contract-first, источник правды — код: Pydantic-схемы и роуты FastAPI → `just openapi` → `backend/openapi.json` (коммитится, CI проверяет актуальность) → TS-клиент. Фаза начинается с PR контракта (`T<фаза>.0`): схемы, роуты-заглушки, `openapi.json`, клиент, моки. Схемы SSE-событий и ошибок `problem+json` объявляйте явно через `responses=`. `specs/api/openapi.yaml` — черновик-вход, не поддерживается параллельно с кодом (specs/05 §0).
- Ядро не знает SystemVerilog: всё SV-специфичное — в `judge/languages/systemverilog/` (ADR-0011).
- Фронтенд: только токены из `tokens.css`, все состояния компонентов из `components.md`, все строки — через next-intl (`messages/ru.json`).
- Код пользователя исполняется только в песочнице (ADR-0003); любые изменения судьи, образа тулчейна или песочницы прогоняют `tests/security/`.
- Модель данных растёт миграциями по фазам; таблицы «на будущее» не создаются.
- PR, который меняет поведение, архитектуру, настройку или эксплуатацию, в том же PR обновляет `docs/`. Документация описывает то, что есть в коде.
- Python-зависимости — Poetry (свой `pyproject.toml` и `poetry.lock` в `backend`, `judge`, `worker`), JS — pnpm.
- Язык интерфейса, задач и документации — русский; идентификаторы, коды ошибок и комментарии в коде — английский.

## Исходные материалы
`brief/` — бриф продукта, бриф дизайна и пакет передачи дизайна (`brief/apparatica-handoff/`: токены, тема Tailwind, темы Monaco, `components.md`, скриншоты экранов). Бриф — исходные данные заказчика: не правьте его, изменения требований вносятся в `specs/`.
